## Safe workflow

1. Read `README.md`, `FIREBASE_SETUP.md`, `admin/DEPLOY.md`, and `docs/HANDOFF_2026-10-28_AR.md` before changes.
2. Never commit service-account JSON, credentials, signing keys, `.env`, or generated hosting config.
3. Run `./gradlew testDebugUnitTest lintDebug lintRelease assembleDebug assembleRelease bundleRelease` after Android changes; run admin tests and Firestore Emulator rules tests too.
4. Use JDK 21 or newer for Firebase Emulator tests. Keep release signing values in environment variables only.
5. Before any public deployment, inspect the live site and get explicit approval. Do not modify Firestore production data/rules without backup and approval.
6. Never update the public APK page or submit to Play until the signing state and current Play `versionCode` are verified.

## Product boundaries

- Public comments are disabled in Release until terms, consent, report/block tools, and ongoing moderation are complete.
- Cloud Functions are not deployed; aggregate reactions remain read-only until a trusted server-side writer exists.
- Android 16/API 36 is required for new Play apps and updates from 2026-08-31. Keep large-screen adaptive UI because Android 16 ignores some orientation constraints on large displays.
- The new Upload key cannot automatically update existing direct-download APKs signed with the old key. Confirm Play App Signing/reset status before submission.
